# OSRS LLM Companion — RuneLite plugin + MCP server

## Architecture

Monorepo with two components:

```
runelite-mcp/
├── plugin/    Java 11 sideloaded RuneLite plugin — game-state data plane
├── server/    TypeScript MCP server — knowledge/compute plane (@modelcontextprotocol/sdk)
├── scripts/   runelite-dev.cmd (Windows sideload launcher)
└── README.md  install + usage + MCP registration docs
```

- **plugin/** embeds a localhost-only REST JSON server: JDK built-in `com.sun.net.httpserver`, bound to `127.0.0.1`, port configurable via plugin config (default 8765), fixed 4-thread pool. No MCP in Java (official Java SDK requires JDK 17; the client is Java 11). No shaded dependencies — uses only the JDK plus classes the client already ships (Gson), avoiding the child-first-classloader `ClassCastException` trap. Strictly read-only: no input, menu-action, or write endpoints.
- **server/** is the MCP server (stdio transport, works with Claude Desktop / ZCode / Cursor; optional `--http` flag). It proxies the plugin and enriches with WOM, OSRS wiki, and GE price APIs, with a disk cache for wiki data.

Distribution is sideload-only (the Plugin Hub rejects "plugins exposing player info over HTTP" outright). Dev loop: `gradlew run` boots a dev client with the plugin. Daily use: fat jar → `%USERPROFILE%\.runelite\sideloaded-plugins` + `java -ea -cp %USERPROFILE%\.runelite\repository2\* net.runelite.client.RuneLite --developer-mode --debug` (script provided; note the stock runelite.exe launcher can never load sideloaded plugins — verified in RuneLite source).

## Plugin HTTP endpoints (all GET, JSON)

| Endpoint | Data | Mechanism (verified against RuneLite master) |
|---|---|---|
| `/health` | game state, username, client online/offline | `GameStateChanged` |
| `/state` | skills real/boosted/XP, HP, prayer, run energy, weight, exact location, world, combat level, account type | `Client` getters + varbits |
| `/quests` | per-quest FINISHED / IN_PROGRESS / NOT_STARTED for all quests + quest points | `Quest.getState(client)` via `ScriptID.QUEST_STATUS_GET`, batched in one `clientThread.invoke`, cached with invalidation |
| `/diaries` | 12 regions × 4 tiers: complete, tasks done, reward claimed, started | gameval varbits `*_DIARY_<TIER>_COMPLETE` / `*_<TIER>_COUNT` / `*_<TIER>_REWARD` / `STARTED_*_DIARY`; Karamja easy-hard on the legacy `ATJUN_*` varbits |
| `/combat-achievements` | 6 tier completions + per-tier task counts | varbits 12863–68 / 12885–90 (per-task detail is interface-only — stretch goal) |
| `/slayer` | current task creature/count/location, points, streak, reward unlocks decoded to names | varps 394/395/2096, varbits 4068/4069/4723, unlock bitfields 1076/1344 decoded via `DBTableID.SlayerUnlock` |
| `/kc` | boss name → killcount | `DBTableID.HiscoresBossesInfo` table walk (boss→varp) on the client thread |
| `/inventory`, `/equipment` | item id/name/qty | `getItemContainer` (always live) |
| `/bank` | last snapshot + timestamp; live view when open | cached on `ItemContainerChanged(BANK)` (bank only exists client-side after being opened) |
| `/collection-log` | aggregate logged count (per-item only when the interface is open — stretch) | hiscores `collections_logged` + widget capture later |
| `/snapshot` | **one-call unified account state**: everything above merged — the highest-value feature | aggregates the above |

All client access is marshaled through `clientThread.invoke` + `CompletableFuture` with a 10s timeout (the Client is not thread-safe). Endpoints return clean "not logged in" payloads when offline.

## MCP server tools

| Tool | Data source |
|---|---|
| `game_state` | plugin `/snapshot` |
| `bank_snapshot` | plugin `/bank` + GE valuation (id/qty × prices) |
| `ge_price` (name or id) | `prices.runescape.wiki/api/v2/osrs` (`/latest`, `/1h`, `/5m`, `/mapping`) + timeseries; cached |
| `quest_info` (name) | recursive prereq chain, skill reqs with boostable flags, rewards — from wiki `Module:Questreq/data` Lua table + `Quest details`/`Quest rewards` templates; disk cache |
| `item_info` (name) | equip reqs, stats, GE price, sources — wiki templates + GE |
| `boss_info` (name) | access requirements, recommended gear/stats by style, strategy summary — wiki strategy pages |
| `solve_requirements` (target quest/boss/item) | recursive delta vs live player state: missing quests (full chain), missing levels, missing items; returns an ordered plan |
| `progress_delta` (period day/week/month) | WOM v2 `GET /players/:name/gained` — public, no key |

All outbound HTTP sends a descriptive `User-Agent` (prices.runescape.wiki pre-blocks generic Java/curl UAs). WOM API key is optional (raises 20→100 req/min; obtained via WOM Discord — only relevant for heavy use).

## Build phases

1. **Plugin skeleton + core state** — scaffold `plugin/` (Gradle, Java 11, `compileOnly net.runelite:client`, lombok), HTTP server, config (port), then implement `/health`, `/state`, `/inventory`, `/equipment`, `/bank`, `/quests`, `/diaries`, `/combat-achievements`, `/slayer`, `/kc`, `/snapshot`. Sideload launcher script. Verify with `gradlew run` + curl.
2. **Server skeleton + game tools** — `server/` with the TS SDK (stdio), `game_state` and `bank_snapshot` tools, graceful "client offline" errors, registration docs for Claude Desktop and ZCode.
3. **Wiki + GE knowledge** — cached wiki fetch layer + Lua table parser; `ge_price`, `quest_info`, `item_info`, `boss_info`; bank valuation wired into `bank_snapshot`.
4. **Requirement solver** — recursive quest-chain resolution + skill/item deltas against live state; ordered plan output (the "DS2 from memory" problem, solved mechanically). Test fixtures from known quest chains (DS2 included).
5. **WOM progress delta** — `progress_delta` tool.
6. **Later / optional** — DPS calculator (vendor `weirdgloop/osrs-dps-calc` `src/lib` — TypeScript but GPL-3.0, so isolated in its own module and flagged), community search (needs Reddit OAuth + YouTube API key from you), per-tick event buffers, screenshots.

## Constraints, risks, and honest limits

- Read-only forever: no clicking/keys/menu automation (Jagex ban + RuneLite rejected-features list). No Plugin Hub submission.
- Bank snapshot is only fresh after you've opened the bank once per session; endpoint reports its timestamp so the LLM can ask you to open it.
- Collection log and CA per-task data are interface-bound: v1 ships aggregates; deep capture is a stretch goal.
- Boss KC: exact via client varps when logged in; falls back to WOM/hiscores (which lag) when offline.
- Prereqs on this machine: JDK 11 (Temurin) and Node 18+; no API keys needed for phases 1–5.

## Verification

- Phase 1 gate: `gradlew run` boots the client; `curl 127.0.0.1:8765/health` responds logged-out; then in-game each endpoint is diffed against the real quest list, diary tab, and slayer gem.
- Server gates: `tsc` clean; unit tests for the Lua table parser and solver (known quest chains as fixtures); MCP handshake via inspector; end-to-end: register the server in an MCP client and produce a correct DS2 gap analysis for your account.
